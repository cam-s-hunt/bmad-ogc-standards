## What this settles

1. **The exit code is useless for linkage.** An untested requirement and a dangling `inherit` both exit 0.
   Only a severity-0 message (a duplicate id here) aborts the compile.
2. **MODSPEC_1 cannot tell requirements from recommendations or permissions.** It fires for all three with
   the word "Requirement". The only distinguishing signal is the identifier prefix (`/req/`, `/rec/`, `/per/`),
   which depends on authors following the convention. The semantic XML (`doc.xml`) is the sturdier input.
   (This confirms the adversarial review's prediction; before today it was code-reading only.)
3. **MODSPEC_2 cannot tell an external prerequisite from a broken internal one.** c1 and c4 produce the same
   message. Cross-standard `inherit` is legitimate, so the rule "fail on any MODSPEC_*" would reject
   conformant documents. The YAML stage (rule G010: declared normative-reference prefixes) is therefore necessary.
4. **Clean documents are not message-free.** c1 has four severity-2 messages. Calibration must be differential
   (a baseline of expected messages), as the gate already supports for its own findings.
5. **Header-class messages are severity 2.** OGC_14 ("Submitters is missing") did not block anything.
